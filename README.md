# Menix AI Job Assistant

This project is the existing Electron + Spring Boot job assistant, with its dashboard styled to follow the supplied Menix references: charcoal/navy surfaces, electric-blue primary actions, green match indicators, a collapsible icon sidebar, six recommendations, a status donut, and source health. The Electron app menu and visible scrollbars are hidden; scroll behavior remains available.

## Run on Windows

1. Extract this ZIP.
2. Start the backend in PowerShell:
   ```powershell
   cd backend
   mvn spring-boot:run
   ```
   The backend uses port 8080 by default. If it is already occupied, stop the old Menix backend or configure a different port and update `API_BASE` in `src/features/job-assistant/job-assistant.js`.
3. In a second PowerShell terminal, return to the project root and run:
   ```powershell
   npm install
   npm start
   ```

## Dashboard behavior

- On desktop, the sidebar stays collapsed to icons until hovered or keyboard-focused, then expands to show navigation labels. Choosing a Workspace item keeps it expanded until you click elsewhere; the account row sits directly above backend status and the Pro upsell remains removed. Narrow phones keep an icon rail.
- Use the account avatar button to choose a PNG, JPG, or WebP profile photo. The image is center-cropped, saved locally on this device, and shown in both the sidebar and dashboard navbar.
- The Electron window uses an integrated dark title bar with working Apple-style close, minimize, and maximize controls.
- Dashboard recommendations are limited to the six highest-scoring real jobs discovered in the last seven days. At wide desktop widths they appear in a 3-column × 2-row grid; smaller viewports reflow to two or one columns.
- The dashboard requests only the top 50 matching listings, skips an unused expensive match-count statistic, and caches successful GET responses for one minute to keep section navigation responsive.
- Application progress and source health stay in full-width stacked cards when the dashboard narrows, so their charts and connection labels remain readable.
- Job results, source health, and application status are loaded from the local Spring Boot API; the dashboard does not fabricate connection states.
- After replacing/updating project files, restart the Spring Boot process from `backend` so new API routes (including Messages & Outreach) are loaded. If an old backend is still running, the Messages page reports that it needs updating instead of showing an unexplained 404.
- Dashboard search filters already loaded job records locally; it does not start a portal search.
- The New Jobs page defaults to recent listings without hiding lower-scoring results; its minimum-match control is independent of the Strong Matches dashboard threshold.
- Public employer-board and Adzuna synchronization is disabled unless `PUBLIC_JOB_FEEDS_ENABLED=true` and its configuration is present. Dashboard and Jobs cards identify each source and mark jobs as **Verified by feed**, **From email alert**, or **Saved by me**. Portal browsing remains user-driven; Menix does not automate restricted search-result collection.
- The dashboard KPI cards span the content width and use the supplied blue, green, purple, and orange reference style. **Search Naukri** opens an official results page using the configured keyword, location, and fresher preference.
- The Jobs page and Application tracker use compact opportunity/status cards, and the top-right dashboard controls include notifications, theme, and profile actions.
- Select **Details** (or the three-dot job-card control) to open the full job description and match details. Use **Back**, the app's browser-history back action, or a two-finger left-to-right touchpad swipe to return to the previous section.
- Saved-job bookmarks use the existing application record with `SHORTLISTED` status; rejected jobs remain available for restoration in the application tracker.
- KPI values and donut segments are derived from API job/application/source records. Match scores come from the backend matching service.
- Provider support and submission permissions remain source-dependent; the dashboard visual refresh does not create new portal permissions or guarantee universal application support.

## Multi-portal job discovery and outreach

- **Naukri discovery is user-triggered.** In AutoApply, enter a keyword and location, select Fresher or Any experience, and choose **Search Naukri** to open the official public results URL. Work-mode filters are applied on Naukri itself when available; Menix does not guess undocumented filter parameters. After the site renders results, choose **Import visible jobs** to read up to 50 rendered `.cust-job-tuple` result cards from the current Naukri page. This action does not scroll, click result cards or Apply, inspect hidden APIs, bypass sign-in/CAPTCHA, or run on a timer. Use the site's own controls and access flow; if Naukri changes its markup or blocks access, import reports that no supported cards were found and you can continue manually. Repeat search/import explicitly when you want to refresh results. Search observations update existing records by Naukri job ID and canonical listing URL; stale jobs and application history are retained.
- **Apply destinations are distinct from listing URLs.** Visible result imports store the original Naukri listing URL and leave the application destination unverified. The Menix card's **Open listing** action opens that original listing in AutoApply; it does not create an application or click Apply. You can click Apply yourself on Naukri, then confirm the resulting page as the Apply link. When a site opens a popup in the embedded browser, Menix asks before attaching that HTTPS destination to the currently saved job. Only a confirmed destination is used by the job card's Apply action; otherwise it opens the original listing. Until confirmed, no destination is invented. A posting date absent from the result card stays unknown; the recent dashboard filter uses the last observation time, not a claim that the job was posted that day.
- **Other job-site browsing** remains supervised. Browse LinkedIn, Google Jobs, Indeed, Glassdoor, or another HTTPS site yourself. **Save this job** appears only when the current HTTPS page looks like an individual job detail page. It first reads JobPosting JSON-LD; if unavailable, it reads visible title, company, location, and description text and asks you to review those fields before saving through the existing manual-job endpoint. Search pages containing multiple postings are not imported by that single-page action. Menix never clicks website controls or submits a form while saving. Sign-in cookies may remain between app launches; Menix does not bypass CAPTCHA/OTP. The selected application is restored when reopening AutoApply, and visible fields are scanned when the employer page finishes loading. Smart Autofill remains an explicit action. Submission requires your explicit confirmation and an employer confirmation before the tracker records it. Closing the embedded tab does not sign you out; sign out on the portal to end a saved login.
- Jobs from configured Company boards, Adzuna, Email alerts, Career pages, and user-saved listings are shown with source and origin indicators. Public-feed sync requires `PUBLIC_JOB_FEEDS_ENABLED=true`; the Daily automatic sync settings independently select which configured source types run and when. Existing application history is retained if a source is later disabled.
- If there are no recommendations, the Dashboard shows source and freshness diagnostics. `GET /api/jobs/diagnostics` reports source counts, retired-source exclusions, the configured verification window, jobs outside the seven-day discovery window, and employer-board configuration status.
- Use **Add a job manually** to save a public HTTPS listing or careers URL. Menix canonicalizes it, prevents duplicate listing URLs, preserves source attribution, and records discovery time separately from any posting date supplied by the provider. A manually saved URL is a bookmark, not a connected or automatically synced feed.
- **Portal capabilities** in Sources reports job-search/detail capability separately from account, inbox, messaging, and submission access. This build does not connect LinkedIn, Naukri, Indeed, or employer inboxes, and does not claim any portal inbox is connected.
- **Messages & Outreach** stores recruiter drafts, contacts, related job URLs, notes, and optional follow-up dates locally in the backend database. Copy a draft and open the portal to send it yourself. Menix records it as sent only after you explicitly confirm the manual action and add evidence; it never sends recruiter messages.
- From **Jobs**, select Apply to open the official HTTPS application page inside AutoApply. The Prepare Application panel distinguishes answered, autofilled, suggested, blank, invalid, and unsupported controls, counts required blanks and recognizable submit controls, explains unmapped questions, and supports a fresh rescan. Required markers are inferred from native accessibility attributes and asterisks in visible labels. Smart Autofill applies only high-confidence non-sensitive profile facts—including generic **Name** fields from the saved candidate name—and, when explicitly enabled in Settings, high-confidence approved answers. Suggested answers remain editable and require your approval; legal/eligibility answers, CAPTCHA/security challenges, custom widgets, and unsupported controls remain manual. The final review rescans the live page and submission stays disabled while any required control is blank or invalid.
- **Smart Apply Memory** in Settings stores facts you explicitly save to your candidate profile and an approved answer library. Matching is deterministic and confidence-based; it does not train a model. Automatic reuse and answer learning can be disabled, saved answers can be excluded or corrected, and individual or all answer history can be deleted. Sensitive saved answers are shown only for explicit confirmation and are never automatically filled. Unmatched low-confidence questions stay blank.
- **Optional AI suggestions require consent for each request.** Menix sends selected resume text, relevant saved job details, and eligible non-sensitive unanswered question labels to the configured Gemini provider only after confirmation. Resume text may contain personal information. Returned drafts are suggestions only and are never filled automatically; the user must review and explicitly approve each answer. External AI can be left unconfigured without affecting basic profile and approved-answer matching.
- **Resume uploads use the employer page's native file chooser.** Menix detects visible file controls and hidden file inputs paired with a clearly labeled visible upload control, but never selects a local file. Choose the intended resume yourself; the selected file goes directly through the employer page's normal upload flow. The saved resume can be downloaded in Menix first.
- **Submission is deliberate and verified.** The Submit Application action appears only after a fresh review finds no visible required fields left blank and one identifiable submit control. Menix asks for confirmation before clicking that control. The tracker is marked `SUBMITTED` only when a recognizable employer confirmation appears; otherwise the status remains unconfirmed for manual follow-up. Duplicate application records are prevented by the existing job/application workflow.
- **Platform limits:** LinkedIn automation is disabled. Google Forms, Greenhouse, Lever, Ashby, Workday, and Workable hosts are recognized for generic accessible form assistance; provider-specific application-form adapters are not validated, and manual completion may be required. The employer-board connectors described below only read public job-posting APIs and do not automate application forms or submissions. Google Forms may use custom/cross-origin controls. Check the employer's current terms before use. Unsupported or prohibited flows must be completed manually.
- Changing an application to `WITHDRAWN` hides it from the active application tracker and returns to **Jobs**. Choosing `NOT_COMPLETED_YET` does the same and makes the job available to start again; both keep the application record. The status editor opens inside the selected application card.
- AutoApply uses `/api/profile`, `/api/resumes`, `/api/resumes/application-draft`, `/api/applications`, and `/api/autofill/*`. Smart Apply Memory adds `GET/POST /api/smart-apply/answers`, `PUT/DELETE /api/smart-apply/answers/{id}`, `POST /api/smart-apply/answers/{id}/used`, collection deletion for answer history, and `GET/PUT /api/smart-apply/preferences`. Persistent records are stored in additive `smart_apply_answer` and `smart_apply_preferences` tables; new user-supplied profile fields are additive columns on `candidate_profile`. Hibernate's existing `ddl-auto=update` creates these additively; no existing application or answer history is deleted.
- The application webview uses context isolation, sandboxing, disabled Node integration, HTTPS navigation restrictions, and no website preload. The preload bridge exposes only the desktop actions needed by the Menix renderer; form interaction remains in the isolated application webview.
- Public URLs must use HTTPS. Manual source testing disables redirects and blocks local/private-network hostnames and addresses. Review each provider's terms and rate limits before use; the source test is only a reachability and format hint, not permission to collect listings.

Run the local AutoApply engine and mock-form/security tests from the project root:

```powershell
npm test
```

### Connecting job sources and refreshing listings

1. Open **Sources** to see five source-type cards: Company boards, Adzuna, Email alerts, Career pages, and Manual. Each shows status, last success/error and latest counts, with **Run now** where a source can sync. Adzuna reports **Not configured** until both API credentials and search profiles are present.
2. In **Settings → Career pages**, add public HTTPS career-page URLs. Menix fetches each page with the `MenixJobAI/1.0 (personal job tracker)` User-Agent after checking that host's `robots.txt`. It imports only `schema.org` `JobPosting` JSON-LD (including arrays and `@graph`), sanitizes descriptions, and does not use CSS selectors, cookies, login, or redirects. A page without supported structured postings reports **No structured job data found**. Configure its schedule in **Settings → Daily automatic sync**, or select **Run now** in Sources. Requests are spaced one second apart, and a failed page request does not refresh job verification. A `validThrough` timestamp is persisted and expired postings are marked closed after their source page is successfully read.
3. For employer boards hosted by Greenhouse or Lever, find the company board identifier in its public careers URL. For example, `boards.greenhouse.io/acme` uses `acme`; `jobs.lever.co/acme` uses `acme`.
4. The **Company boards** section in Sources lets you add and remove Greenhouse, Lever, Ashby, Workable, and SmartRecruiters identifiers in the local database. Use **Test board** before enabling a board. Suggested companies use candidate identifiers and ATS providers only; each remains unverified until the test endpoint succeeds. Company-board UI changes apply without restarting the backend.
5. Alternatively, in the PowerShell window used to start the backend, set comma-separated identifiers and restart Spring Boot:
   ```powershell
   $env:GREENHOUSE_BOARD_TOKENS="acme,contoso"
   $env:LEVER_SITE_NAMES="acme,contoso"
   $env:ASHBY_BOARD_NAMES="acme,contoso"
   $env:WORKABLE_ACCOUNTS="acme,contoso"
   $env:SMARTRECRUITERS_COMPANIES="acme,contoso"
   $env:PUBLIC_JOB_FEEDS_ENABLED="true"
   mvn spring-boot:run
   ```
   Set only the board variables for sources you want. Environment identifiers and enabled database boards are merged, with duplicates ignored. Employer-board sync stays disabled unless `PUBLIC_JOB_FEEDS_ENABLED=true`; these are public posting identifiers, not account credentials. Requests use a 10-second timeout, a one-request-per-second provider throttle, one retry on 5xx, and bounded `Retry-After` backoff for 429 responses. Redirects are not followed and private/local addresses are blocked. If no usable source is configured, the Dashboard says **No sources configured. Add sources in Sources.**
   To enable Adzuna, configure `ADZUNA_APP_ID` and `ADZUNA_APP_KEY` in the backend environment and optionally set `ADZUNA_DAILY_CALL_CAP` (default `200`). The saved search profiles are editable in **Settings → Adzuna search profiles**. Profiles are stored in the local database; each runs once per sync with at most three pages of 50 results. Daily request usage is persisted and displayed in Sources. The connector requests Adzuna's India endpoint, limits results to seven days, orders by date, and does not follow `redirect_url`; it stores that HTTPS URL as the application destination. Use credentials issued by Adzuna and observe the applicable API terms and plan limits.
6. On the Dashboard, choose **Search Naukri**, or open AutoApply and enter job search preferences. Search and import from Naukri are explicit user actions; there is no scheduled Naukri collector. After Naukri displays result cards, select **Import visible jobs**. The Dashboard and Jobs page default to Full Stack Developer and fresher listings; the location filter accepts Remote, On-site, Hybrid, or a city. To verify an application URL, open an imported job, click Apply on Naukri yourself, and confirm the resulting page in AutoApply. You can also select LinkedIn, Google Jobs, Indeed, Glassdoor, or enter another HTTPS site and save a single job detail page.
7. Menix reads only the currently open page after your explicit save action. It does not automate portal searches, collect result lists, connect accounts, or bypass sign-in, CAPTCHA, or other site controls.

### Daily automatic sync

- In **Settings → Daily automatic sync**, choose the device-local time, enable/disable the daily run, optionally run enabled sources when Menix opens, and select Company boards, Adzuna, Email alerts, and Career pages individually. These settings are stored in the local backend database. The backend scheduler checks the selected time once a minute and runs at most once per local day. The Electron app-open option runs once per app launch.
- Each source must also be configured and enabled in its own settings: public feeds require `PUBLIC_JOB_FEEDS_ENABLED=true`; Adzuna requires `ADZUNA_APP_ID` and `ADZUNA_APP_KEY`; Email alerts require the mailbox importer toggle; Career pages require enabled URLs. Manual jobs are not synchronized. **Run now** is a user-triggered per-source action and remains available regardless of the daily schedule selection.
- A failed source run reports an error and does not close listings or refresh their verification timestamps. Existing jobs, saved jobs, and application history remain available.

### Email job-alert importer

- Create job-alert emails yourself on Naukri, LinkedIn, Indeed, or Glassdoor, then configure **Settings → Email job-alert importer**. The importer is off by default, uses IMAP over TLS, reads message content only after the From address matches the editable allowlist, and does not save email bodies. The eight anonymized fixtures under `backend/src/test/resources/email-alerts` exercise the four parsers; sender patterns and templates have not been verified against a real mailbox.
- For Gmail, use an app password after enabling 2-Step Verification and IMAP. Menix encrypts a password saved in Settings with AES-GCM; by default the encryption key is stored outside the repository at `%USERPROFILE%\.menix-job-assistant\email-alert.key` on Windows. Keep the key file protected and backed up securely if you need to retain the encrypted setting. Alternatively, set `EMAIL_ALERT_IMAP_PASSWORD` in the backend environment and optionally set `EMAIL_ALERT_KEY_FILE`; do not put actual credentials in `.env.example` or commit them.
- Settings and mailbox operations use the local Spring API. The backend binds to `127.0.0.1` and accepts the Electron renderer's `null` origin; do not expose or port-forward this service. Save settings before **Test connection**: it checks login/folder access and counts allowlisted messages without importing or marking them seen.
- Email alerts run when selected by the Daily automatic sync schedule or through **Run now** in Sources, provided the email-importer toggle is enabled. Processed Message-IDs prevent repeat imports. Messages are marked seen only when that option is selected. Imported listings carry an **From email alert** badge, **Summary only · unverified** marker, and no verified application destination; their discovery time, not an invented posting date, controls the seven-day recommendation window. Menix does not follow email tracking redirects.
- To manually configure an environment password, set `EMAIL_ALERT_IMAP_PASSWORD` in the same PowerShell process used to start the backend. Never paste a real app password into logs, source control, or support messages.

### Job freshness and reconciliation

- Feed observations keep provider posting time separate from first discovery, last observation, and last verification. Jobs are recommended only when a source observed them open within the configured verification window; the default is 48 hours and can be changed with `JOB_VERIFICATION_MAX_AGE_HOURS`.
- The Dashboard date selector filters by posting date (24 hours, 7 days, older, or all dates). Exact provider timestamps are required for the 24-hour window; date-only values can qualify for wider windows, while unknown dates are labeled unverified. A wider date filter does not bypass the verification window.
- Source sync attempts, last successful sync, per-run counts, and the latest error are persisted in the local database. Failed requests do not close jobs or refresh their verification timestamps. Jobs omitted by a feed are retained conservatively.
- Manually saved portal links are bookmarks, not automatically verified openings. Legacy records without verification metadata remain unverified until a configured feed genuinely observes them.
- Use **Sources → Reconcile job data** to mark legacy, stale, and invalid records for review. The operation does not delete jobs or application history; it reports duplicate URL candidates and preserves saved/application records.

- Run backend tests from the project root with `mvn -f backend/pom.xml test`.
